# TrustLens v2 Perception 模块 Context 总结

## 1. 模块定位

`app.perception` 是文档感知层，目标是把不同来源的文档输入统一转换为 `DocumentIR`：

- **输入**：原生 PDF、扫描 PDF、图片。
- **中间事实**：`ObservationIR`，表示页面上物理存在的“一行文本 + bbox”。
- **语义提示**：`SemanticRegion`，由 Docling 提供区域类型、bbox、辅助文本、阅读顺序。
- **表格提示**：`TableRegion`，由 PyMuPDF 提供精确网格，或由 Docling 提供只有 bbox 的表格区域。
- **输出**：`DocumentIR`，包含：
  - `observations`：物理事实层；
  - `elements`：按阅读顺序排列的结构层；
  - `conflicts`：冲突与异常记录；
  - `metadata`：统计信息。

核心设计原则：

1. **Observation 是权威文本来源**，Docling 文本只做辅助与交叉验证。
2. **表格重建优先使用 PyMuPDF 网格**，无网格时用扫描线投影重建。
3. **语义区域与物理观察分离**，通过 `observation_ids` 引用，避免对象嵌套膨胀。
4. **多页 PDF 分 native / non-native 调度**：native 主进程串行，non-native 进程池并行。
5. **容器大框不删除**，只标记 `is_container`，残余 observation 按 Y 轴切分成 fragment。

## 3. 核心数据模型

### 3.1 `BBox`

轴对齐边界框，原点为页面左上角。

字段：`x0, y0, x1, y1`

属性：`width, height, area, center_x, center_y`

方法：

- `intersects(other)`
- `contains(other)`
- `overlap_ratio(other)`：交集 / 自身面积
- `intersection_over(other)`：交集 / other 面积，用于判断“other 是否几乎被 self 覆盖”
- `to_tuple()` / `from_tuple()`

### 3.2 `ObservationIR`

物理事实层，一行文本。

字段：

- `page`
- `text`
- `bbox`
- `source`：`pymupdf | pdfplumber | rapidocr | paddleocr`
- `confidence`
- `char_bboxes`
- `font / font_size / color / flags`

### 3.3 `SemanticRegion`

Docling 等工具输出的语义区域提示。

字段：

- `page`
- `bbox`
- `type`：粗粒度语义类型
- `docling_label`：原始细粒度标签
- `docling_text`：Docling 辅助文本，不进入最终权威文本
- `source`
- `confidence`
- `raw_meta`
- `is_container`
- `container_group_id`
- `reading_order_index`

`SemanticRegionType` 包括：

- 结构块：`table, picture, chart`
- 文本块：`paragraph, title, list, caption, footnote, reference, code, formula, index`
- 页面级：`header, footer`
- 表单：`form_field, checkbox, empty_value`
- 特殊：`handwritten, gradient_text, marker`

### 3.4 `TableRegion` / `GridCell`

`GridCell`：`row, col, bbox`

`TableRegion`：

- `page`
- `bbox`
- `rows / cols`
- `cells`
- `source`：`pymupdf | docling`
- `has_grid`
- `docling_label`
- `reading_order_index`

PyMuPDF 来源有网格；Docling 来源通常无网格。

### 3.5 `DocumentIR`

最终输出。

字段：

- `file_path`
- `page_count`
- `page_dimensions`
- `observations: List[ObservationIR]`
- `elements: List[DocumentElement]`
- `conflicts: List[Dict]`
- `metadata: Dict`

### 3.6 `DocumentElement`

结构层元素。

字段：

- `reading_order_index`
- `page`
- `bbox`
- `element_type`
- `docling_label`
- `docling_text`
- `source`：`docling | fallback_orphan`
- `text`
- `table`
- `observation_ids`
- `is_container_fragment`
- `container_group_id`
- `local_conflicts`

`element_type` 可为 `SemanticRegionType` 之一，或 `orphan_paragraph`。

### 3.7 `Table` / `TableCell`

`TableCell`：

- `row, col`
- `text`
- `bbox`
- `rowspan, colspan`
- `observation_ids`

`Table`：

- `page`
- `bbox`
- `rows, cols`
- `cells`

旧模型 `TextBlock`、`Picture` 保留兼容，新代码不再使用。

## 4. 顶层流水线：`PerceptionPipeline`

`PerceptionPipeline` 是 perception 层顶层入口。

构造参数：

- `max_workers=4`
- `docling_do_ocr=None`
- `force_ocr_for_pdf=False`
- `deskew_min_angle=0.2`
- `pdf_render_dpi=200`

内部组件：

- `PdfObservationExtractor`
- `ImageObservationExtractor`
- `ImagePreprocessor`
- `PyMuPDFTableDetector`
- `DocumentIRBuilder`
- 按 `do_ocr` 缓存的 `DoclingRegionParser`

入口：

```python
run(context, page_num=None, is_native_pdf=None) -> DocumentIR
```

流程：

1. 解析 MIME。
2. 图片文件 → `_run_image_path()`。
3. PDF：
   - 若 `is_native_pdf is None`，调用 `_detect_native_pdf()`。
   - native → `_run_native_pdf_path()`。
   - non-native → `_run_non_native_pdf_path()`。

### 4.1 Native PDF 路径

组件并行：

- `PdfObservationExtractor.extract`
- `PyMuPDFTableDetector.detect`
- `DoclingRegionParser.parse(do_ocr=False)`

若指定 `page_num`，给 Docling 传 `page_range=(page_num, page_num)`，并在结果中过滤页。

最后调用：

```python
builder.build(
  observations=...,
  semantic_regions=...,
  pymupdf_tables=...,
  page_count=...,
  page_dimensions=...,
  file_path=...,
  pymupdf_enabled=True,
)
```

### 4.2 Non-native PDF 路径

要求必须指定 `page_num`，否则抛错。

流程：

1. 用 PyMuPDF 把指定页渲染成临时 PNG，DPI 由 `pdf_render_dpi` 控制。
2. 构造临时 `DocumentContext`，MIME 为 `image/png`。
3. 走 `_run_image_path()`。
4. `finally` 清理临时 PNG。

### 4.3 Image 路径

流程：

1. `ImagePreprocessor.preprocess()` 做 deskew。
2. 若产生临时图，替换 `context.file_path`。
3. 并行：
   - `ImageObservationExtractor.extract`
   - `DoclingRegionParser.parse(do_ocr=True)`
4. 强制把 `obs.page` 和 `region.page` 覆盖为 `target_page`。
5. 调用 `builder.build(..., pymupdf_tables=[], pymupdf_enabled=False)`。
6. `finally` 清理 deskew 临时文件。

### 4.4 Native 判定

`_detect_native_pdf()`：

- 计算平均文本字符数。
- 计算平均图片覆盖率。
- 判定条件：
  - `avg_text > 100`
  - `avg_coverage < 0.5`

### 4.5 页面尺寸

`_get_page_info()`：

- PDF：PyMuPDF 读取所有页尺寸；单页模式只返回目标页尺寸。
- 图片：根据 observation 的最大 `x1/y1` 估算单页尺寸。

## 5. 多页编排：`MultiPagePdfOrchestrator`

用于整本 PDF 处理。

构造参数：

- `non_native_workers=4`
- `dpi=200`
- `native_text_threshold=100`
- `native_coverage_threshold=0.5`

`PageProfile`：

- `page_num`
- `is_native`
- `text_chars`
- `image_coverage`

流程：

1. `_probe_pdf_pages()` 逐页探测 native。
2. 分场景：
   - 混合页：native 主线程处理，non-native 子线程 + ProcessPool。
   - 全 native：主进程串行。
   - 全 non-native：ProcessPool。
3. `_merge_document_irs()` 合并。

关键设计：

- Native 页不 worker 化，复用同一个 `PerceptionPipeline(docling_do_ocr=False)`。
- Non-native 页 ProcessPool 并行，每个 worker 独立加载 `PerceptionPipeline(docling_do_ocr=True)`。
- Worker 全局变量：`_non_native_pipeline`、`_worker_dpi`。

合并时：

- 按页排序。
- `observations` 直接拼接。
- `elements` 的 `page` 对齐。
- `element.observation_ids` 加 offset。
- `table.cells[].observation_ids` 也加 offset。
- `conflicts` 覆盖 page。
- 最终按 `(page, bbox.y0, bbox.x0)` 重排 `reading_order_index`。

注意：最终合并阶段会按页和几何位置重新分配全局阅读顺序，可能覆盖页内 Docling 顺序。

## 6. 提取器细节

### 6.1 `PdfObservationExtractor`

使用 PyMuPDF `page.get_text("dict")`。

处理：

- 遍历 `blocks -> lines -> spans`。
- 过滤空文本。
- 过滤白色 / 近似白色文本：`color_int >= 0xEFEFEF`。
- 过滤异常字号：默认 `min_font_size=1.0`，`max_font_size=500.0`。
- 过滤明显超出页面边界的坐标。
- 已移除 `flags` 过滤，避免误删斜体文本。
- 合并行 bbox 与文本。
- 输出 `ObservationIR(source="pymupdf", confidence=1.0)`。

### 6.2 `ImageObservationExtractor`

使用共享 RapidOCR。

流程：

1. 加载图片，cv2 优先，PIL fallback。
2. 调用 `get_shared_rapidocr()`。
3. OCR 结果格式：`poly, text, confidence`。
4. 过滤空文本、过长/过短文本。
5. 原始 bbox 由 poly 的 min/max 得到。
6. 可选 `_refine_bbox_with_ink()`，用墨迹分析收紧行 bbox：
   - ROI 截取：横向 padding 稍宽，纵向 padding 极克制（≤3px），防止侵入邻行。
   - 稳健二值化：用 `p85/p10` 估计对比度，对比度 < 20 直接返回空，阈值取 `p_bg - contrast * 0.45`。
   - 去横线：形态学开运算提取长横线（表格边框/下划线）并从 mask 减去。
   - 连通域过滤合并：面积过滤、扁平杂波过滤、垂直中心一致性校验、高度跨度校验，最后合并为一个 bbox。
   - 物理门禁：收紧后宽/高不足原始框 35% 则放弃收紧。
7. 收紧失败时回退到 OCR 原始 bbox。
8. 输出 `ObservationIR(source="rapidocr")`。

设计要点：
- 只输出单个行级 bbox，**不做字符切分**（交给下游 Visual Engine）。
- 失败即回退，宁可放弃也不输出错误收紧结果。
- 通过"纵向 padding 克制 + 中心先验 + 门禁"三重机制，防止上下行碎片并入本行。

### 6.3 `DoclingRegionParser`

职责：

- 输出语义区域类型 + bbox；
- 附带 Docling 文本；
- 标记祖先容器；
- 记录 Docling 阅读顺序。

构造参数：

- `do_ocr=False`
- `use_rapid_ocr=True`
- `mark_parent_containers=True`
- `parent_min_children=2`

`_get_converter()`：

- 延迟创建 `DocumentConverter`。
- 配置 `PdfPipelineOptions`。
- 关闭：
  - `do_table_structure`
  - `do_picture_classification`
  - `do_picture_description`
  - `do_code_enrichment`
  - `do_formula_enrichment`
  - `generate_page_images`
  - `generate_picture_images`
- 若 `do_ocr=True` 且 `use_rapid_ocr=True`，使用 `RapidOcrOptions`。

`parse()`：

- 尝试 `converter.convert(file_path, page_range=...)`。
- 旧版不支持则整文档转换，之后由 Pipeline 过滤页。
- `doc.iterate_items()` 生成 `SemanticRegion`，`reading_order_index` 为枚举顺序。

`_item_to_region()`：

- 从 `prov` 获取页码。
- `_extract_bbox()` 用 `bbox.to_top_left_origin(page_height)` 转左上原点。
- 多 prov 合并 min/max。
- `_classify_item()`：
  - `TableItem -> table`
  - `PictureItem -> chart / picture`
  - `TextItem -> LABEL_TO_TYPE 映射，默认 paragraph`

`_mark_parent_containers()`：

- 用 `intersection_over > 0.95` 判断包含。
- 找平行子节点，数量 >= `parent_min_children` 则标记容器。
- 设置 `is_container=True` 和 `container_group_id`。
- 不删除任何 region。

`_SUPPRESSIBLE_TYPES` 定义可被容器标记处理的类型。

### 6.4 `PyMuPDFTableDetector`

使用 `page.find_tables()`。

输出：

- `TableRegion`
- 总 bbox
- `GridCell` 列表
- `source="pymupdf"`
- `has_grid=bool(cells)`
- 不提取文本，文本由 observation 认领。

支持 `page_num=None` 所有页，或指定页。

## 7. 构建与融合细节

### 7.1 `RegionAssigner`

非表格区域认领 observation。

策略：

- 小区域优先：按 `bbox.area` 升序。
- 匹配规则：
  - observation 中心点在 region 内；
  - 或 IoU >= `iou_threshold`，默认 0.3。
- 一个 observation 只能被一个 region 认领。

返回：

```python
(region_idx -> [obs_idx], unassigned_obs_idx)
```

### 7.2 `TableReconstructor`

构造参数：

- `cell_iou_threshold=0.1`
- `gap_ratio=0.02`

入口：

```python
reconstruct(region, observations, obs_indices=None) -> Table
```

先过滤在表格内的 observation：中心在表格内或 IoU > 0.3。

两种路径：

#### 有网格路径

- 对每个 observation 找最佳 IoU 的 `GridCell`。
- IoU >= `cell_iou_threshold` 则放入桶。
- 每个 cell 内 observation 按 `(center_y, center_x)` 排序。
- 拼接文本，回填 `observation_ids`。

#### 无网格路径：`_assign_with_scan`

复杂扫描线算法：

1. **Y 轴行聚类**
   - 按 `center_y` 排序。
   - `y_tolerance = max(3.0, avg_height * 0.4)`。
   - 中心接近或垂直重叠 >= 0.4 归为同一行。
   - 生成 `row_edges`。

2. **X 轴列分割**
   - 分行局部 gap 探测。
   - 扫描线计算 `depth(x)`。
   - 合并相邻同深度段。
   - 找波峰段。
   - `min_depth`：`num_rows > 3` 时为 `max(2, int(num_rows * 0.25))`，否则 1。
   - 近邻波峰合并，`min_col_width = max(avg_char_w * 3, table_bbox.width * 0.02)`。
   - 取中点作为列割线，生成 `col_edges`。

3. **区间感知词距反向验证与拆词**
   - 对跨越列割线的 observation，估算字符宽度。
   - 在 margin 区间内找空格。
   - 拆成左右 observation，保留原 `orig_idx`。

4. **虚拟网格构建与 colspan 分配**
   - 按 Y 重叠选最佳行。
   - 按首字符中心、末字符中心确定起止列。
   - 计算 `colspan`。

5. **生成最终 TableCell**
   - 合并同一 cell 的 observation。
   - 文本拼接，`colspan` 取最大，`rowspan=1`。
   - 回填 `observation_ids`。

设计原则：宁可把 merged cell 拆成多个格子，也不遗漏 bbox。

### 7.3 `DocumentIRBuilder`

纯函数构建器，不做 I/O。

构造参数：

- `table_merge_iou_threshold=0.5`
- `region_iou_threshold=0.3`
- `text_similarity_threshold=0.7`
- `container_fragment_gap_ratio=0.5`
- `orphan_y_gap_ratio=0.8`

`build()` 流程：

1. **分离表格区域与非表格区域**
   - `type == "table"` 为 Docling 表格。
   - 其他为普通区域。

2. **抑制被表格覆盖的冗余 region**
   - 若某 region 被任意 table bbox 覆盖超过 95%，丢弃。
   - 原因：Docling 关闭 `do_table_structure` 后，会把 cell 降级为 paragraph region。

3. **合并表格区域**
   - PyMuPDF 与 Docling 表格按 IoU >= 0.5 合并。
   - 两者都识别：保留 PyMuPDF 网格，继承 Docling 的 `reading_order_index` 和 `docling_label`。
   - PyMuPDF 独有：直接保留。
   - Docling 独有：生成 `TableRegion(source="docling", has_grid=False)`。
   - 冲突：
     - `pymupdf_missed_table` 仅在 `pymupdf_enabled=True` 时记录。
     - `docling_missed_table` 不再记录，只记 metadata 计数。

4. **重建表格**
   - 对每个合并表格，取中心在表格 bbox 内的 observation。
   - 调用 `TableReconstructor.reconstruct()`。
   - 标记已消费 observation 索引。

5. **非表格区域认领**
   - 剩余 observation 交给 `RegionAssigner.assign()`。

6. **构建 DocumentElement 流**
   - 表格元素：`element_type="table"`，`observation_ids` 来自 cell。
   - 非表格 region：
     - 容器 region：残余 observation 按 Y 切分 fragment，生成 `is_container_fragment=True` 的元素。
     - 普通 region：含 picture/chart；文本拼接；空文本且非 picture/chart 则跳过。
     - 文本类 region 会与 `docling_text` 做相似度检查，低于阈值记录 `docling_text_mismatch` 到 `local_conflicts`。
   - 孤立 observation：`_build_orphan_elements()` 按同页 + Y 邻近合并成 `orphan_paragraph`，`source="fallback_orphan"`。

7. **排序与重分配阅读顺序**
   - 有 order 的元素按 `(order, page, y0, x0)`。
   - 孤儿元素按 `(page, y0, x0)` 几何插入。
   - 最终重分配 `reading_order_index`。

8. **记录 conflicts**
   - `unassigned_observation`
   - `docling_text_but_no_obs`
   - `empty_region`

9. **组装 DocumentIR**
   - 写入 metadata 统计。

关键 metadata：

- `observation_count`
- `element_count`
- `semantic_region_count`
- `semantic_region_with_text_count`
- `container_region_count`
- `pymupdf_table_count`
- `docling_table_count`
- `merged_table_count`
- `table_element_count`
- `suppressed_region_inside_table`
- `container_fragment_count`
- `orphan_element_count`
- `table_merged_both`
- `table_pymupdf_only`
- `table_docling_only`

PerceptionError

## 11. 设计决策与注意事项

1. **Docling 只做语义提示**，最终文本以 Observation 为准。
2. **PyMuPDF 表格检测不取文本**，只提供网格，文本由 Observation 认领。
3. **表格合并采用方案 C**：PyMuPDF 网格 + Docling 阅读顺序/标签。
4. **Docling 关闭 `do_table_structure`**，因此表格内 cell 可能降级为 paragraph region，Builder 会抑制被 table bbox 覆盖 95% 以上的 region。
5. **图片路径不跑 PyMuPDF 表格检测**，所以 Docling 独有表格不记 `pymupdf_missed_table` conflict。
6. **容器大框不删除**，只标记 `is_container`，残余 observation 按 Y 切分。
7. **多页最终阅读顺序会按页和几何位置重排**，可能覆盖页内 Docling 顺序。
8. **`observation_ids` 是全局索引**，多页合并时必须对 element 和 table cell 做 offset 重映射。
9. **Non-native PDF 整文档处理必须走 Orchestrator**，不能直接 `PerceptionPipeline.run(page_num=None)`。
10. **临时文件清理**：deskew 临时图、PDF 渲染临时图都在 `finally` 中清理。
11. **RapidOCR 单例线程安全**，但在 ProcessPool 中每个子进程独立加载。
12. **潜在风险点**：
    - Native 判定阈值硬编码；
    - Docling `page_range` 旧版本兼容性；
    - 扫描线表格重建对空格和字符宽度估算敏感；
    - 小区域优先认领可能抢 observation，但表格内 region 已被抑制；
    - 多进程下 Docling 模型加载内存开销较大。

---

以上可作为 TrustLens v2 `perception` 模块的完整上下文摘要。核心一句话：**它把 PDF/图片通过 PyMuPDF、RapidOCR、Docling 三种能力提取为 Observation + SemanticRegion + TableRegion，再由 DocumentIRBuilder 融合成带阅读顺序、表格结构、冲突记录的 DocumentIR。**





# TrustLens v2 Metadata Analysis 模块 Context 总结

## 1. 模块定位

`app.forensics.metadata` 是 TrustLens v2 的 **L1 元数据取证层**，目标是从文档中提取并分析：

- 文件系统与 ExifTool 元数据；
- PDF 结构、对象图、修订历史、加密信息；
- 数字签名与证书；
- 图片底层结构（JPEG/PNG）；
- XMP 历史、软件来源、时间线；
- 生成器指纹与文档类型风险。

最终产出两类结果：

1. **`List[Evidence]`**：统一证据对象，供下游 Risk Engine / LLM Detective 使用；
2. **`ForensicContext`**：清洗后的高密度 LLM 上下文，遵循“四工具 Raw Metadata → LLM Context 清洗规范”。

整个模块通过 `MetadataEngine` 编排，并被 `LangGraph` 取证图作为 `l1_metadata` 节点调用。整体取证图还包含 L2 视觉、L3 语义、L4 验证，但当前 L2 有真实实现，L3/L4 为占位。

## 5. 收集器（Collectors）

### 5.1 `ExifToolCollector`

- 执行：
  ```bash
  exiftool -j -G1 -a -charset utf8 -All <file>
  ```
- 强制 UTF-8，`errors="replace"`，超时 30s。
- 解析 JSON 为 `ExifToolMetadata`。
- 日期解析采用白名单格式，不盲目猜测：
  - `%Y:%m:%d %H:%M:%S`
  - `%Y:%m:%d`
  - `%Y-%m-%d %H:%M:%S`
  - `%Y-%m-%dT%H:%M:%S`
  - `%Y-%m-%d`
  - `%d/%m/%Y %H:%M:%S`
  - `%a %b %d %H:%M:%S %Y`
- 提取文档身份、文件系统时间、XMP History、EXIF 详细、MakerNotes 存在性。
- 返回 `{"metadata": ExifToolMetadata}`。

### 5.2 `QPDFCollector`

- 执行 `qpdf --check <file>` 和 `qpdf --show-xref <file>`。
- 解析：
  - `PDFStructureReport`：有效性、修订数、增量更新、xref 错误、警告、线性化。
  - `encryption_info`：加密、算法、权限、密码保护。
  - `revision_details`：从 `--show-xref` 解析修订详情。
- 返回 `{"structure": ..., "encryption_info": ..., "revision_details": ...}`。

---

## 6. 解析器（Parsers）

### 6.1 `PikepdfParser`

- 使用 `pikepdf` 打开 PDF。
- 构建 `ObjectGraph`：
  - 总对象数、流数量。
  - 检测 `/ObjStm` 对象流。
  - 检测嵌入文件、JavaScript、Launch、OpenAction。
  - 提取注释、附加动作、嵌入文件详情、活跃内容详情。
  - 检测孤立对象（从 Root 不可达）。
  - 页面 XObject 关系，填充 `pages_with_xobjects` 和 `edges`。
- 返回：
  ```python
  {
    "object_graph": ObjectGraph,
    "has_acroform": bool,
    "has_layers": bool,
    "has_annotations": bool,
    "object_stream_count": int,
    "total_objects": int,
    "embedded_files_detail": list,
    "active_content_detail": dict,
    "orphan_objects": list,
    "annotations_pikepdf": list,
    "additional_actions": list,
  }
  ```

### 6.2 `PyMuPDFParser`

- 使用 `fitz` 遍历页面。
- 提取：
  - `fonts_per_page`：页码 -> 字体名列表。
  - `images_per_page`：页码 -> 图像数。
  - `semantic_text_pages`：页码 -> 全文。
  - `annotations_detail`：注释详情。
  - `forms_detail`：表单字段。
  - `anomalous_regions`：出界文本、极小文本。
  - `page_order_confidence`：默认 1.0。
  - `font_distribution`：字体覆盖率。
  - `image_summary`：图像尺寸聚合。
  - `color_distribution`：颜色覆盖率。
  - `size_distribution`：字号覆盖率。
  - `replacement_chars`：U+FFFD 替换字符。
  - `text_overlaps`：文本重叠。
  - `image_dpi`：图像 DPI 估算。
- 返回上述字段组成的字典。

### 6.3 `SignatureParser`

- 使用 PyMuPDF 检测签名 Widget。
- 使用 `pdfsig` 验证签名完整性与证书状态。
- 使用 `cryptography` 交叉验证证书有效期和颁发者 CN。
- 返回：
  ```python
  {
    "signature_fields": list,
    "signatures": list,
    "has_signatures": bool,
    "signature_status": str,  # NO_SIGNATURE / HAS_SIGNATURE / VERIFIED / BROKEN
    "pdfsig_available": bool,
    "cryptography_available": bool,
  }
  ```

### 6.4 `ImageStructuralParser`

- 解析 JPEG：
  - APP 段、JFIF、EXIF、Photoshop 资源。
  - DQT 量化表指纹、估算质量。
  - DHT 完整表数据、按 ITU-T Annex K 判定 standard/optimized/mixed。
  - SOF 编码类型、尺寸。
  - marker 序列、尾部游离字节。
  - 缩略图存在性。
- 解析 PNG：
  - IHDR、pHYs、PLTE、IDAT、IEND。
  - 文本块 tEXt/zTXt/iTXt。
  - 关键块完整性。
- 返回结构化字典，供 `MetadataContainer` 和 `ContextBuilder` 使用。

---

## 7. 分析器（Analyzers）

### 7.1 `XMPAnalyzer`

- 提取 XMP History 链，产出 `XMP_HISTORY_CHAIN`。
- 检测 `CreatorTool` 与 `Producer` 矛盾，产出 `METADATA_SOFTWARE`。
- 检测 `DerivedFrom` / `OriginalDocumentID`，产出 `GENERIC_OBSERVATION`。

### 7.2 `ConsistencyAnalyzer`

综合多源数据，检测：

- 时间线矛盾：`TEMPORAL_INCONSISTENCY`。
- 结构-软件交叉：`PDF_INCREMENTAL_UPDATE`、`GENERIC_OBSERVATION`。
- 字体-软件关系：`FONT_INCONSISTENCY`。
- 页面尺寸不一致：`PAGE_DIMENSION_INCONSISTENCY`。
- XMP 格式不匹配：`XMP_FORMAT_MISMATCH`。
- XMP MetadataDate 晚于 CreateDate：`XMP_METADATA_AFTER_CREATE`。
- 编码异常：`METADATA_ENCODING_ANOMALY`。
- 公司字段不匹配：`COMPANY_METADATA_MISMATCH`（需外部传入 expected_company）。
- 文件系统时间与 PDF ModifyDate 差异：`FS_VS_PDF_TIME_DIFF`。
- 对象流异常：`OBJECT_STREAM_ANOMALY`。
- 表单/图层/注释检测：`ACROFORM_DETECTED`、`LAYERS_DETECTED`、`ANNOTATIONS_DETECTED`。
- 过度嵌入图像：`EXCESSIVE_EMBEDDED_IMAGES`。
- 对象图异常：`OBJECT_GRAPH_ANOMALY`、`EMBEDDED_OBJECT_FOUND`。
- 隐藏文本：`HIDDEN_TEXT_DETECTED`（基于颜色分布中白色文本）。
- 图片专用一致性：
  - `IMAGE_DIMENSION_MISMATCH`
  - `THUMBNAIL_INCONSISTENCY`
  - `JPEG_QUALITY_MISMATCH`
  - `JPEG_DQT_ANOMALY`、`JPEG_DHT_ANOMALY`、`PNG_CHUNK_ANOMALY`、`JPEG_HEADER_CORRUPTION`

### 7.3 `FingerprintAnalyzer`

- 从 `ExifToolMetadata` 提取 Creator、Producer、XMP CreatorTool、Software 等。
- 调用 `FingerprintRegistry.match()` 匹配生成器。
- 产出：
  - `METADATA_SOFTWARE`：识别出的生成器。
  - `PRODUCER_FINGERPRINT_MISMATCH`：生成器与文档类型关系及风险分数。
  - `METADATA_SOFTWARE`：Creator/Producer 工具链映射。
  - `GENERIC_OBSERVATION`：多匹配痕迹。
- 不做风险判断，只输出事实，由上层推理。

### 7.4 `SignatureAnalyzer`

- 基于 `SignatureParser` 输出，产出：
  - `CERTIFICATE_EXPIRED`
  - `CERTIFICATE_REVOKED`
  - `SIGNATURE_TIME_MISMATCH`
  - `SIGNER_ISSUER_INFO`（纯事实，证书颁发者 CN）
  - `MULTI_SIGNATURE_INCONSISTENCY`

---

## 8. 指纹库（Registry）

### 8.1 `FingerprintRegistry`

- 加载 `fingerprints.yaml`。
- `match(metadata, header_binary, pdf_version)`：
  - 遍历 producers。
  - 匹配 `fingerprints.metadata`、`header_binary`、`structure`。
  - 计算置信度 `total_weight / max_possible_weight`。
  - 返回 `List[FingerprintMatch]` 按置信度降序。
- `get_document_type_risk(producer_name, document_type)`：
  - 返回 `(risk_level, risk_score)`。
  - 风险等级：`low`, `medium`, `high`, `critical`, `unknown`。
- `detect_creator_producer_mismatch(creator, producer)`：
  - 使用 `TOOL_CATEGORIES` 关键词库识别工具类别。
  - 返回映射关系，如 `office_suite -> image_editor`。

### 8.2 `fingerprints.yaml`

定义多个 producer，例如：

- 办公软件：Microsoft Word、LibreOffice。
- Adobe：Acrobat、Photoshop、InDesign。
- 在线设计：Canva。
- 系统：macOS Quartz、Microsoft Print to PDF、PDFium。
- 转换引擎：Ghostscript、Skia/PDF。
- TeX：pdfTeX、LuaTeX。
- PDF 库：iText、ReportLab、FPDF。
- 在线转换：PDF24、PDF2Go。
- AI 生成：ChatGPT PDF。
- 图片编辑/相机：Photoshop Image、Lightroom、GIMP、iPhone、Android、Canon、Sony、Canva Image。

每个 producer 包含：

- `name`, `category`, `risk_baseline`
- `fingerprints.metadata/header_binary/structure`
- `document_type_risk`：针对不同文档类型的风险等级。

## 11. 设计原则与注意事项

### 11.1 设计原则

1. **收集器只采集，不产证据**；解析器深度解析；分析器跨源推理产证据。
2. **部分失败优雅降级**：单个收集器/解析器/分析器失败不影响整体，错误记录到 `_errors`。
3. **证据去重**：基于 `Evidence.__hash__`。
4. **双轨输出**：`List[Evidence]` 和 `ForensicContext`。
5. **清洗规范**：删除表示冗余，保留潜在有用事实；语义信息损失敏感，结构信息可压缩。
6. **指纹分析纯事实**：`FingerprintAnalyzer` 只输出识别结果和注册表风险分数，不做最终判断。
7. **签名分析纯事实**：证书颁发者信息一律提取，不因文档类型过滤。
8. **日期解析白名单**：不盲目猜测，无法解析则丢弃并 warning。

### 11.2 潜在问题与注意点

- `ImageStructuralFingerprint` 中 `jpeg_encoding_type` 重复定义。
- `ContextBuilder` 中使用了 `container._filesystem_timestamps` 和 `container._file_name`，但 `MetadataContainer` 定义的是 `filesystem_timestamps` 和 `file_name`，可能不一致。
- `MetadataEngine._assemble_container` 中部分字段映射可能遗漏或覆盖。
- `fingerprint_matcher` 的 `header_binary` 是十六进制字符串，而 `fingerprints.yaml` 中 pattern 是字节转义（如 `\\xB5\\xB5\\xB5\\xB5`），匹配逻辑可能不准确。
- L3/L4 尚未实现，风险引擎为简单占位。
- `ForensicState` 使用 Pydantic + `field(default_factory=list)`，但 Pydantic v2 中应使用 `Field(default_factory=list)`，当前写法可能不标准。
- `graph.py` 中 `MemorySaver` 导入路径可能因 LangGraph 版本而异。
- `nodes.py` 中 L2 视觉分析依赖 `app.forensics.visual`，但未在本次上下文中提供。
- `ConsistencyAnalyzer` 中部分检测依赖 `parsed_data` 的键，需确保 `MetadataEngine` 正确传入。
- 图片专用分析依赖 `image_type` 和 `image_structural_details`，需确保 `ImageStructuralParser` 被调用。

TrustLens v2 的 `metadata` 模块是一个以 `MetadataEngine` 为核心、以 `ExifTool/QPDF/pikepdf/PyMuPDF/Signature/ImageStructural` 为采集解析工具、以 `XMP/Consistency/Fingerprint/Signature` 为分析器、以 `ForensicContext` 为 LLM 上下文载体的 L1 元数据取证流水线；它通过 LangGraph 与 L2 视觉、L3 语义、L4 验证层协同，最终产出统一 `Evidence` 和结构化报告。







# TrustLens v2 Visual Engine 模块 Context 总结

## 1. 模块定位

`app.forensics.visual` 是 TrustLens v2 的 **L2 视觉取证层**，目标是从文档的**底层渲染信息**中提取物理证据，检测纯逻辑层（metadata、OCR、语义）无法发现的视觉伪造痕迹。

核心能力：

- **Native PDF**：提取 span/char/drawing/image 对象级 IR，检测字体/字号/颜色离群、span 碎裂、字符重叠、矢量覆盖、局部转曲、对象复用等；
- **Digital Image / 扫描 PDF**：渲染成图后切割字符级 IR，检测基线偏离、表格列对齐异常、Camera vs Digital 分类；
- **Cross-page**：通过 `VisualIR` 汇总跨页证据。

最终产出两类结果：

1. **`List[Evidence]`**：统一证据对象，供下游 Detective LLM 推理；
2. **`VisualContext`**：清洗后的视觉层 LLM 上下文（对应 Metadata 层的 `ForensicContext`）。

整个模块通过 `VisualEngine` 编排，被 LangGraph 取证图的 `l2_visual` 节点调用。当前 L2 已实现真实模型，L1 已完成，L3/L4 仍为占位。

## 6. 来源判定与编排

### 6.1 `SourceTypeDetector`

判定规则：

- **image MIME / extension** → `DIGITAL_IMAGE`
- **PDF** → 抽样最多 5 页，计算平均字符数：
  - `avg_chars >= 100` → `DIGITAL_PDF`
  - `avg_chars < 100` → `DIGITAL_IMAGE`（**扫描 PDF**，路由到 image 路径）
- 其它 → `UNKNOWN`

关键设计：**低文本密度的 PDF 被归为 `DIGITAL_IMAGE`**，由 orchestrator 逐页渲染 + Camera 分类器处理。

### 6.2 `CameraDigitalClassifier`

判定图片是 digital 还是 camera-captured。

核心洞察：

- **native 数字图**：像素值离散（软件渲染），某几个精确值吸纳大量像素；
- **实拍图**：像素值连续（光照/传感器），值分散在连续区间。

三个正向特征：

1. **纯色度（Solid Color Ratio）**：局部 std < 阈值的像素占比（`solid_ksize=15`, `std_threshold=3.0`）
2. **峰宽（Peak Width）**：灰度/饱和度直方图最强峰的半高宽度（256 bins）
   - native 1-4 bins；相机 10-30 bins
3. **峰集中度（Peak Concentration）**：最强 bin 占全图像素比例
   - native 30-70%；相机 5-15%

评分公式：

```
sharpness = min(
    min(gray_w_score, gray_c_score),
    min(sat_w_score, sat_c_score)
)
score = 0.4 * solid + 0.6 * sharpness
```

- `score >= 0.55` → `DIGITAL_IMAGE`
- 否则 → `CAMERA`（**该页跳过字符切割分析**）

### 6.3 `VisualOrchestrator`

按 source type 分派：

**DIGITAL_IMAGE**：
- **PDF**（扫描件）→ 逐页 `render_pdf_page()` → `_process_non_native_page()`
- **图片** → `_process_pure_image()`

**DIGITAL_PDF**：
- 逐页 `_classify_page_type()`：
  - 若 observation 只有 `pymupdf` → `native_pdf` → `_process_native_page()`
  - 若有 `rapidocr/paddleocr` → `non_native_pdf` → `_process_non_native_page()`

**Native PDF 页**：

```python
span_extractor.extract(pdf_path, document_ir, pages=[page_num])
drawing_extractor.extract(pdf_path, pages=[page_num])
image_extractor.extract(pdf_path, pages=[page_num])
```

**Non-native / Pure image 页**：

1. 渲染/加载图 → `img: np.ndarray`
2. `CameraDigitalClassifier.classify(img)`
3. 若 `CAMERA`：`VisualPageIR` 仅记录 `image_classification`，**跳过字符切割**
4. 否则：`ImageCharSegmenter.extract_from_array(img, all_observations, page_num, document_ir)`

## 7. 提取器细节

### 7.1 `PdfSpanExtractor`

使用 `page.get_text("rawdict")`。

流程：

1. 遍历 `blocks → lines → spans → chars`
2. `_build_span()`：
   - 从 chars 重建 text
   - 提取 bbox、origin、font_name、font_size、font_color、flags
   - 构造 `span_id = f"p{page}_b{block}_l{line}_s{span_index}"`
3. `_attach_span()`：
   - **匹配规则**：span 中心点在 observation.bbox 内 **OR** IoU ≥ 0.5
   - 命中 → `observation_spans[obs_idx]`
   - 未命中 → `orphan_spans`
4. `_attach_elements()`：
   - 从 `document_ir.elements` 读取 `observation_ids`，反查 span 归属
   - 填充 `element_spans`、`element_types`、`element_roi`

关键点：

- **页码基于 1**
- `observation_id` 是 **DocumentIR.observations 的全局索引**
- 不做任何过滤/判定（字号、颜色异常交给 Analyzer）

### 7.2 `PdfDrawingExtractor`

使用 `page.get_drawings()`。

- 遍历 items，标记 `has_bezier / has_line / has_rect`
- **累加 `bezier_count`**（每次 `op == "c"` 累加 1），供 `OverlapAnalyzer` 复用检测的 `bezier_count >= reuse_min_bezier` 判定使用
- 计算 `items_hash`（**形状哈希**，用于复用检测）
  - 关键：PyMuPDF 的 item 是 Point / Rect / Quad 对象，用 `_format_coords()` 展开并归一化到 bbox 原点
- 提取 `fill / stroke / fill_opacity / stroke_opacity`
- 标记 `is_micro`（width/height < 5.0 pt）

### 7.3 `PdfImageExtractor`

使用 `page.get_image_info(xrefs=True)`。

- 提取 `bbox / width / height / xref / digest`
- `digest` 由 PyMuPDF 提供，用于图像复用检测

### 7.4 `ImageCharSegmenter`

从图像 + DocumentIR observations 中切割字符。

入口：

- `extract(image_path, document_ir)` → 加载图片，遍历所有 obs
- `extract_from_array(image_bgr, all_observations, page_num, document_ir)` → 用于已渲染的数组

**单 observation 处理流程**：

1. ROI 截取（obs.bbox）
2. `_robust_ink_segmentation()`：百分位法
   - `p2, p98 = percentile(gray, (2, 98))`
   - rescale 到 0-255
   - GaussianBlur 估算背景 → subtract → Triangle 二值化
3. `_remove_structural_lines()`：形态学开运算去除长横线
4. `connectedComponentsWithStats` 提取连通组件
5. X 轴深度重叠合并（`_merge_overlapping`，处理 'i', ':', '.'）
6. `_reconcile_box_count()`：**强制劈开/熔合**使 box 数 == `len(text.strip())`
7. 逐字符构建：
   - `_apply_y_density_protection()`：防止 '1' / 'I' 高度坍塌
   - 计算 `ink_density / black_level / aspect_ratio`
   - 标记 `typography_class`（reliable / uncertain / excluded）
   - 标记 `inference_flag`（observed / split_inferred / merged_inferred）
   - 计算 `global_line_confidence`（整行切割质量）

字符分类：

- `_PUNCTUATION_CHARS`：`.,:;'"()[]{}-_+=*&^%$#@!\/|<>~`` → `EXCLUDED`
- `_UNCERTAIN_CHARS`：`gjpqyJQ` → `UNCERTAIN`
- 其他 → `RELIABLE`

窄字符集：`_NARROW_CHARS = set("1Il|i:;.,'")` → 密度阈值降到 1.0

## 8. Analyzer 详解

所有 Analyzer 继承 `BaseVisualAnalyzer`，签名：

```python
def analyze(self, visual_ir: VisualIR) -> AnalyzerResult
```

`AnalyzerResult`：

- `anomalies: List[VisualAnomalyIR]`
- `context: Dict[str, Any]`（中性观察）

约定：

- 输入：完整 `VisualIR`
- 输出：`AnalyzerResult`
- 部分 Analyzer 支持 `set_document_ir(document_ir)` 注入 DocumentIR

### 8.1 `TypographyAnalyzer`（三层样式离群）

**三层独立检测**：

- **Global**：跨文档的字体/字号/颜色稀有 bar
- **Page**：单页内的稀有 bar
- **Element**：语义单元内的稀有 bar

核心方法：`_find_rare_bars(histogram)`

- 用 **log 空间 + MAD** 找稀有 bar
- 权重用 **char count**（不是 span count），避免"长 span 被当 outlier"
- `min_bar_char_count = 2` 过滤 fallback 字体

三层结果合并（`_merge_anomalies`）：

- 同一 span 被多层命中 → 合并 `reasons`，记录 `scopes`，confidence 加分

**Element type 降权**：

- `ALLOWED_ANOMALY_ELEMENT_TYPES`（header/footer/title/caption/...）命中 outlier 时降到 `allowed_type_confidence = 0.3`

产出：`PDF_TYPOGRAPHY_OUTLIER`

Context：

- `global`：全局三元组列表
- `by_page`：每页的三元组
- `by_table_element`：每个 table element 的三元组

### 8.2 `FragmentationAnalyzer`（span 碎裂）

**分组依据**：DocumentIR 的 element（语义单元），而非 PyMuPDF block/line。

Fallback：无 element 时按 `line_key` 分组。

检测方法：

1. 过滤纯标点/符号 span
2. `min_spans_per_group = 3` 且 `min_group_chars = 20`
3. `log(length)` + MAD 找 outlier（`mad_k = 3.5`）
4. 组级：`avg_len < over_fragmented_avg_len (3.0)` 且 `count >= 5` → 报"组过度碎裂"
5. 兜底（组太小）：`_single_char_check()` 检查孤立单字符 span

产出：`PDF_SPAN_FRAGMENTATION_ANOMALY`

### 8.3 `CharSpacingAnalyzer`（字符重叠 + 数字字形离群）

**A. Char Overlap**：

- 相邻 char bbox 水平重叠
- **动态阈值**（基于较窄字符宽度）：
  - 标点后 + 悬臂字符前：`0.45`
  - 仅一侧匹配：`0.28`
  - 默认：`0.12`
- 悬臂字符集：`T F P V W Y r v w y 4 A L`
- **2D 垂直解耦**：标点与前一字符 Y 轴重合 < 20% → 豁免
- 产出：`PDF_CHAR_SPACING_ANOMALY`（`detection_reason="adjacent_char_bbox_overlap"`）

**B. Numeric Glyph Outlier**：

- 分组：`(font_name, font_size, style_bits)`
- 判定 tabular / proportional：
  - 组内数字宽度 CV < 0.01 → tabular（全局检测）
  - 否则 → proportional（按 digit 分组）
- 检测方法：
  - `n <= 10`：Dixon Q 检验（`DIXON_Q_CRIT` 临界值表）
  - `n >= 11`：MAD 修正 Z-score（`width_mad_k = 3.5`）
- 产出：`PDF_CHAR_SPACING_ANOMALY`（`detection_reason="tabular/proportional_digit_width_outlier"`）

### 8.4 `OverlapAnalyzer`（四大子检测器）

**4.1 Occlusion Detector**：

- 检测大覆盖小（`coverage >= 0.9`）
- 有效 occluder 判定：
  - vector：必须有 fill，`fill_opacity >= 0.9`，min(w,h) >= 1.0
  - image：必须未被 DocumentIR 确认为合法 picture/chart
  - text：必须颜色差 >= 100 通道值
- 排除：细线覆盖细线、被覆盖者面积 < `occlusion_min_area`
- 产出：`PDF_OBJECT_OCCLUSION`

**4.2 Object Reuse Detector**：

- **只做 vector / image**（文本复用已删除，B2B 发票正常）
- Vector：`items_hash` 相同 + `bezier_count >= 3` + `item_count >= 5` + 尺寸相似 + 位置不同
- Image：`digest` 相同
- 产出：`PDF_OBJECT_REUSE`

**4.3 Overlay Characterization**：

- 只对 occlusion 中"半透明 vector 或 image"补充描述
- 产出：`PDF_OVERLAY_CHARACTERIZATION`

**4.4 Correlation Engine**：

- 找 "occlusion + reuse 同 pair" 的证据
- 产出：`PDF_COPY_MOVE_CORRELATION`

Context：

- `object_pool`（text/vector/image 计数）
- `near_occlusions`（coverage 0.7-0.9 之间的）
- `duplicate_groups`（按 hash 分组）

### 8.5 `OutliningAnalyzer`（局部转曲）

思路：

- 筛选含 ≥ 3 贝塞尔曲线的 drawing
- 长宽比符合字符（0.15 - 6.0）
- 判定该 drawing 是否落在"文本行空白间隙"：
  - Y 轴在行 band 内（±2.0pt）
  - X 轴中心不在任何 span 内

产出：`PDF_PARTIAL_OUTLINING`

### 8.6 `VectorSpoofingAnalyzer`（微型矢量笔画）

流程：

1. 收集结构区域（DocumentIR 的 table/chart bbox + 几何结构线）
2. 筛选微型矢量（`width < micro_threshold` 或 `height < micro_threshold`）
   - `micro_threshold = min(5.0, ref_font_size * 0.6)`
3. 排除：
   - 落在结构区域内
   - 下划线类（`h <= 2` 且 `w >= 10` 且有 line/rect）
4. 剩余候选与 char bbox 相交（`coverage >= 0.3`）

产出：`PDF_VECTOR_SPOOFING`

Context：`micro_vector_candidates`（上限 50 条）

### 8.7 `ImageBaselineAnalyzer`（基线偏离）

对每个 text element 内的每一行字符：

1. 只用 **RELIABLE + 高置信度** 字符做 RANSAC 拟合 baseline
   - `global_line_confidence * local_char_confidence > 0.8`
2. `RANSACRegressor(residual_threshold=median_height * 0.05)`
3. `measurement_uncertainty = max(1.5, median_height * 0.03, inlier_std * 2)`
4. 对每个字符计算 `residual = ink_bottom_y - expected_y`
5. `z = |residual| / measurement_uncertainty`
6. `z > 2.0` → 报出
7. **UNCERTAIN 字符（g/j/p/q/y）只允许"向下"残差**

产出：`IMAGE_BASELINE_ANOMALY`

Context：每个 element 的 baseline 拟合统计（slope/intercept/inlier_count/...）

### 8.8 `ImageAlignmentAnalyzer`（表格列对齐）

1. 分离跨列 / 单列 cell：`colspan > 1` 的 cell 整体跳过，不占用任何 obs
2. 单列 cell 按 `(row, col)` 稳定排序
3. 对每个单列 cell：
   - 从 `cell.observation_ids` 反查候选 chars（`obs_to_chars`）
   - **用 `cell.bbox` 过滤 chars**：
     - char 的 `ink_bbox` 中心点落在 `cell.bbox` 内（左闭右开，避免相邻 cell 边界重复认领）
     - 或 `char.ink_bbox ∩ cell.bbox ≥ 50% char 面积`
   - **全局 char 去重**：同一 char 只能归属一个 cell（按 (row, col) 顺序先到先得）
   - **无 chars 落在 cell 内 → 跳过该 cell，不 fallback 到 `obs.bbox`**
     （原始 obs.bbox 覆盖整行，会让列对齐错位）
4. 用保留的 chars 的 `ink_bbox` 并集作为该 cell 的代表 bbox
5. `mad_L / mad_M / mad_R`，argmin 判定主对齐轴（L/M/R）
6. 对主对齐轴跑 modified z-score
7. 判定 outlier：`z > 3.5` 且 `abs_offset > 6.0`
8. **表头协同豁免**：前两行内异常列数 ≥ 2 → 全豁免

产出：`IMAGE_ALIGNMENT_ANOMALY`

Context：
- 每个 table element 的列级别统计
- `filter_stats`：
  - `skipped_colspan`：跨列 cell 数
  - `skipped_no_obs`：cell 无 obs 或无 bbox
  - `skipped_no_chars`：cell 内无任何 char
  - `used_char_bbox`：成功产出 char 边界的 cell 数
  - `chars_filtered_out`：落在 cell 外被过滤的 char 判定次数
  - `chars_duplicated`：被多个 cell 争抢、只归第一个的 char 次数
- `forgiven_header_anomaly_count`

## 13. 设计决策与注意事项

### 13.1 设计原则

1. **提取器只做物理提取**，不做任何判定；
2. **Analyzer 产双轨**：`anomalies`（判定结果 → Evidence）+ `context`（中性观察 → VisualContext）；
3. **VisualIR 只在 Visual Engine 内部使用**，不进入 ForensicState 下游字段；
4. **Span 是唯一文本分析单元**，按 PyMuPDF 原生边界切分；
5. **observation_id 是全局索引**，由 `PdfSpanExtractor` 从 `document_ir.observations` 反查；
6. **Camera 页直接跳过字符分析**，只记录分类结果；
7. **扫描 PDF 归为 DIGITAL_IMAGE**，由 orchestrator 逐页渲染处理；
8. **Native / Non-native 混合 PDF** 按页类型分别处理。

### 13.2 关键机制

1. **形状哈希**：`items_hash` 归一化到 bbox 原点，是形状平移不变哈希（复用检测）；
2. **图像 digest**：字节级 md5，用于图像复用检测；
3. **表头协同豁免**：前两行异常列 ≥ 2 → 全豁免（避免表头格式差异误报）；
4. **数字字形分支**：tabular（CV 检测）+ proportional（按 digit 分组）双路径；
5. **Y 轴密度保护**：`ImageCharSegmenter` 防止 '1' / 'I' 高度坍塌；
6. **强制劈开/熔合**：`_reconcile_box_count()` 使 box 数 == 字符数；
7. **2D 垂直解耦**：CharSpacingAnalyzer 对"标点落在角落"的假阳性豁免；
8. **RANSAC baseline 拟合**：避免个别下伸字符带偏基线。

### 13.3 潜在问题与注意点

- `PdfDrawingExtractor` 的 `bezier_count` 在 `_extract_page_drawings` 中**未真正累加**（`op == "c"` 时只 `has_bezier = True`，`bezier_count` 始终为 0）——影响 `OverlapAnalyzer._reuse_group_key` 里的 `bezier_count >= self.reuse_min_bezier` 判定；
- `PdfDrawingExtractor` 中存在冗余 `import`（`from typing import Dict, List, Optional` 和 `from typing import Any, List` 重复）；
- `ImageCharSegmenter._robust_ink_segmentation` 与 `ImageObservationExtractor._robust_ink_segmentation` 是**两份独立实现**（逻辑不同），未来可抽公共 `InkAnalyzer`；
- `OverlapAnalyzer._detect_occlusions` 是 O(n²) 双重循环，大页可能慢；
- `ImageAlignmentAnalyzer._collect_by_column` 里 `cells_sorted` 按 colspan 降序处理"先到先得"，未明确 `seen_obs_ids` 的跨 cell 全局去重语义（跨列 cell 的 obs 也会被标记）；
- `VisualOrchestrator._classify_page_type` 只判断 observation source，若同页同时有 pymupdf 和 rapidocr，会归为 non_native；
- `SourceTypeDetector` 对 native PDF 的文本阈值硬编码 100；
- `ImageCharSegmenter._reconcile_box_count` 的"劈开"总是劈最宽的 box，可能劈错字符；
- `CharSpacingAnalyzer` 的 Dixon 临界值表只到 n=10，超过则走 MAD；
- `TypographyAnalyzer._build_context` 对 table element 只处理 `element_type == "table"`，其它 element 的样式上下文不进入 `by_table_element`；
- `VisualContextBuilder` 不做 anomalies 处理，异常走 Evidence 通道，这是有意设计。

### 13.4 与其它模块的关系

- **上游**：`DocumentIR`（Perception 层产出）——提供 observation/element/table，用于 Span 归属和 cell 对齐；
- **并行**：`MetadataEngine`（L1）——相互独立，通过 `state.all_evidences` 汇总；
- **下游**：`Detective LLM` / `Risk Engine`——消费 `Evidence` 和 `VisualContext`；
- **编排**：`ForensicGraph.l2_visual` 节点。

## 14. 核心调用链

### Native PDF

```text
VisualEngine.analyze
  -> SourceTypeDetector.detect
  -> VisualOrchestrator.build_visual_ir
    -> 逐页 _process_native_page
      -> PdfSpanExtractor.extract
      -> PdfDrawingExtractor.extract
      -> PdfImageExtractor.extract
  -> 7 个 Analyzer.analyze
  -> anomaly_to_evidence / source_classification_to_evidence
  -> VisualContextBuilder.build
```

### Digital Image / 扫描 PDF

```text
VisualEngine.analyze
  -> SourceTypeDetector.detect
  -> VisualOrchestrator.build_visual_ir
    -> 逐页 _process_non_native_page / _process_pure_image
      -> render_pdf_page / load_image_bgr
      -> CameraDigitalClassifier.classify
        -> CAMERA: 只记录 classification，跳过字符切割
        -> DIGITAL: ImageCharSegmenter.extract_from_array
  -> 7 个 Analyzer.analyze
  -> ...
```

### LangGraph 接入

```text
l2_visual 节点:
  engine = VisualEngine()
  evidences, vctx = engine.analyze(context, document_ir=state.document_ir)
  state.add_evidences("L2", evidences)
  state.visual_context = vctx.model_dump() if vctx else None
```

---

## 15. 一句话总结

TrustLens v2 的 `visual` 模块是一个以 `VisualEngine` 为核心、以 `SourceTypeDetector` 判定文档类型、以 `VisualOrchestrator` 分派 native/non-native/image 三条路径、以 `PdfSpanExtractor/PdfDrawingExtractor/PdfImageExtractor/ImageCharSegmenter` 为提取器、以 9 个 Analyzer 为检测器、以 `VisualContext` 为 LLM 上下文的 L2 视觉取证流水线。它通过 `Evidence` 通道输出异常判定，通过 `VisualContext` 通道输出中性观察，两者一起供下游 Detective LLM 综合推理。核心设计是**只输出物理事实 + 中性观察，不做最终判断**，与 Metadata 层的"事实层只输出事实"原则一致。
