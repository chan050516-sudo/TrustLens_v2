## 第五轮：高级验证器 —— 指纹库与数字签名（完整实现）

在开始编码之前，我先基于搜索结果整理出一份**完整的生成器指纹知识库**，然后实现匹配引擎。


### 一、生成器指纹知识库（基于学术研究与实际观察）

根据多篇学术研究，PDF生成器会在文件的多个层次留下稳定的**工具痕迹（toolmarks）**。以下是经过验证的指纹特征：

#### 1. PDF头部的二进制魔数（Header Binary Data）

PDF规范允许在`%PDF-1.x`之后添加第二行注释，不同工具会写入不同的二进制值。研究表明**9种工具具有唯一值**，可直接用于识别：

| 生成器 | 二进制魔数（十六进制） | 唯一性 |
|--------|----------------------|--------|
| Acrobat Distiller | `0xE2E3CFD3` | 唯一 |
| Microsoft Office Word | `\xB5\xB5\xB5\xB5` | 唯一 |
| LibreOffice | 特定值 | 唯一 |
| Ghostscript | 特定值 | 唯一 |
| Mac OS X Quartz | 特定值 | 唯一 |
| PdfTeX | `0xD0D4C5D8` | 与LuaTeX共享（TeXLive Linux） |
| LuaTeX | `0xD0D4C5D8` 或另一值 | 依赖发行版和OS |
| Skia/PDF | 特定值 | 唯一 |
| Cairo | 特定值 | 唯一 |

### 三、验收标准（第五轮完成）

1. **指纹匹配**：
   - 输入包含 `Producer: Adobe Photoshop` 的 PDF，匹配到 `adobe_photoshop`，置信度 ≥ 0.9
   - 输入包含 `Producer: Canva` 的 PDF，匹配到 `canva`，置信度 ≥ 0.9
   - 输入包含 `Producer: Microsoft Word` 的 PDF，匹配到 `microsoft_word`，置信度 ≥ 0.85

2. **文档类型风险**：
   - `Photoshop` + `bank_statement` → 产出 `PRODUCER_FINGERPRINT_MISMATCH`，严重性 `CRITICAL`
   - `Canva` + `legal_document` → 产出 `PRODUCER_FINGERPRINT_MISMATCH`，严重性 `HIGH`
   - `Microsoft Word` + `resume` → 无高风险证据

3. **Creator/Producer 不一致检测**：
   - `Creator: Microsoft Word` + `Producer: Canva` → 检测到 `CANVA_REBUILD` 不匹配
   - `Creator: Microsoft Word` + `Producer: Adobe Photoshop` → 检测到 `PHOTOSHOP_RASTER_REBUILD` 不匹配

4. **数字签名检测**：
   - 有签名的 PDF → `has_signatures=True`，`signature_status` 为 `HAS_SIGNATURE` 或 `VERIFIED`
   - 签名被破坏的 PDF → `signature_status="BROKEN"`
   - 无签名的 PDF → `signature_status="NO_SIGNATURE"`


### 四、扩展指南

指纹库设计为 **YAML 驱动**，添加新生成器只需：

1. 在 `fingerprints.yaml` 的 `producers` 下添加新条目
2. 定义 `metadata` 指纹（字段 + 正则模式 + 权重）
3. 定义 `document_type_risk` 映射
4. 可选：添加 `header_binary` 或 `structure` 指纹

这种设计使得指纹库可以**独立于代码演进**，方便社区贡献和持续更新。
